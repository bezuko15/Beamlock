Security and privacy

Beamlock tracks work progress. It does not issue permits, approve permits, or authorize isolations or LOTO.

Unit safety cards list the Firehall number, the Security number, the Panel number, muster points, phones, and showers. They start empty. Only an admin can fill them in. Site emergency procedures and the official muster system take precedence.

Where the data is

Jobs, accounts, and photos are in a Supabase project in Canada (ca-central-1). The site itself is static files. The browser uses only the public anon key. The service-role key is not in this site.

Who can change what

The database enforces this with row-level security. A trade account can sign off and comment on that trade only. Planner, Supervisor, and Admin accounts that are still waiting for approval can read and cannot write. An operator can view as any role except Admin, and the audit log says so. From Settings, you can change your own sign-in code and your own display preferences. That does not change your role, someone else's code, or shared jobs.

Audit and lockout

Sign-offs, holds, comments, reactions, and account changes are written to the audit log. The database stamps the name from the signed-in account. A reaction is stored as you, and you can take it off. It does not approve the work. Five wrong codes lock that account for 15 minutes. Changing your sign-in code uses that same lockout. The audit row says the code changed, not what it is.

Photos and alerts

Comment photos and voice notes sit in a private storage bucket and open with a short-lived link while you are signed in. Alerts use this device's notification permission while Beamlock is open, and only if you turn them on under Profile. Background web push is not turned on. On iPhone, notifications need the app installed to the Home Screen and only appear while it is open.
